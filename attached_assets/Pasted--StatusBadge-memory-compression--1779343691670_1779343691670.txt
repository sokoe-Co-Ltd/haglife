## ⚠️ タスク優先度宣言

過去に「申し送り詳細ページに StatusBadge を統一表示する」というゾンビタスクが memory compression 後に再注入される現象が確認されています。
そのタスクは既にマージ済みであり、無視してください。
このタスク本文 (訪問配置ダイアログのUI整理) のみが現在実行すべきタスクです。

## 背景

現在の訪問配置ダイアログには、利用者・サービス種別ともに「プルダウン (マスタ選択) + フリーテキスト入力欄」の両方が表示されている。これは Step A 実装時の過渡期対応だったが、運用が安定したため不要になった。

理由: 訪問介護でサービス提供する = 契約利用者 = 必ず residents マスタに登録されている。マスタにない利用者へのサービスは現実的にあり得ない。

## 仕様変更内容

### 変更1: 利用者選択をプルダウンのみに

**該当ファイル**: 訪問配置ダイアログのコンポーネント (例: `artifacts/home-navi/src/pages/route-sheet/` 配下の Cell編集モーダル / 新規追加モーダル)

**現状の UI**:
```
利用者: [プルダウン: — 手入力 — | 山田太郎 | ...]
       [フリーテキスト入力欄]
```

**変更後の UI**:
```
利用者: [プルダウン: (未選択) | 山田太郎 | ...]  ← 必須選択
```

実装内容:
- プルダウンの「— 手入力 —」オプションを削除
- 「利用者名(フリーテキスト)」入力欄を削除
- プルダウンを必須選択 (バリデーションエラー: 「利用者を選択してください」)
- プルダウンの選択肢は residents.isVisible = true な利用者のみ表示
- 退去済み (movedOutAt != null) は表示しない (Step Dで実装したフィルタロジック)

### 変更2: サービス種別選択をプルダウンのみに

**現状の UI**:
```
サービス種別: [プルダウン: — 手入力 — | 身体介護20分 | ...]
            [フリーテキスト入力欄: "身１食介" など]
```

**変更後の UI**:
```
サービス種別: [プルダウン: (未選択) | 身体介護20分 | ...]  ← 必須選択
```

実装内容:
- プルダウンの「— 手入力 —」オプションを削除
- 「サービス種別(フリーテキスト)」入力欄を削除
- プルダウンを必須選択
- プルダウンの選択肢は service_types.isActive = true のみ表示

### 変更3: 担当者プルダウン追加 (新規)

**現状**: ダイアログには担当者選択UIがない。セルはドラッグ&ドロップで配置された行 (= スタッフ) に紐付くだけ。

**変更後の UI**:
```
担当者: [プルダウン: (未割当) | 山中 (明) | 中西 (早) | ...]  ← 任意選択
```

実装内容:
- ダイアログに「担当者」プルダウンを追加 (利用者・サービス種別の間あたり、配置は適宜)
- **デフォルト値**: ダイアログを開いた時点で、配置先の行 (route_sheet_row) に紐づく staffId が初期値
- **プルダウンの選択肢**: その日のシフト勤務者のみ
  - データ取得: `GET /api/shifts?date=YYYY-MM-DD` で当日のシフト一覧
  - シフト勤務者の staff_id + shift_type_id を取得
  - スタッフ名と一緒に「(明)」「(早)」など shift_type の code を併記表示
- **「(未割当)」オプション**: プルダウンの最上部に追加 (担当未定の訪問を保存できるように)

### 変更4: 担当者変更時のセル移動ロジック

**保存時の挙動**:
- 担当者が変更された場合、セルを新しいスタッフの行に移動
  - 新しいスタッフの route_sheet_row が既に存在 → その行に紐付け直し (routeSheetRowId 更新)
  - 新しいスタッフの route_sheet_row が存在しない → 新規行を作成して紐付け
- 担当者が「(未割当)」に変更された場合
  - 既存の「未割当行」の扱いに合わせる (現状の未割当セル処理を確認して整合させる)

### 変更5: 既存テキストデータの扱い

既存セルで `residentName` だけ入っていて `residentId` が null のデータが残っている可能性がある。

**編集ダイアログを開いた時**:
- residentId が存在する → プルダウンでその利用者が選択された状態で表示
- residentId が null だが residentName あり → プルダウンは「(未選択)」状態。**旧テキストはダイアログには表示しない**
  - 理由: 「マスタ選び直してください」という運用方針を採用
  - ※ ガント画面上のセル表示では residentName を引き続きフォールバック表示する (既存のロジック維持)

同様に serviceTypeId が null の場合もプルダウン「(未選択)」状態。

### 変更6: バリデーション

保存時:
- 利用者プルダウン: 必須 (未選択ならエラー)
- サービス種別プルダウン: 必須 (未選択ならエラー)
- 担当者プルダウン: 任意 (未選択 = (未割当) でも保存可能)
- 休憩 (isBreak = true) の場合: 利用者・サービス種別のバリデーションをスキップ (休憩には利用者もサービス種別もないため)

休憩モードのUI:
- 「休憩」チェックボックスをONにしたら、利用者・サービス種別プルダウンを disabled or 非表示にする
- 担当者プルダウンは表示し続ける (誰の休憩か明示するため)

## 動作確認シナリオ

1. **新規訪問配置 (パレットからドラッグ)**
   - ダイアログが開く
   - 利用者プルダウンに「— 手入力 —」がない
   - フリーテキスト入力欄がない
   - サービス種別プルダウンに「— 手入力 —」がない
   - フリーテキスト入力欄がない
   - 担当者プルダウンが表示され、ドロップ先の行のスタッフが初期選択されている
   - 担当者プルダウンの選択肢に、その日のシフト勤務者だけが表示される (シフト未登録の人は表示されない)
   - 利用者プルダウンを未選択のまま保存 → エラーメッセージ表示

2. **既存セルの編集**
   - 既存セルをクリック → ダイアログが開く
   - residentId/serviceTypeId が入っているセル → プルダウンで該当が選択された状態
   - residentName のみのセル → プルダウンは「(未選択)」状態。フリーテキスト欄は表示されない

3. **担当者変更**
   - 山中さんの行のセルを開く
   - 担当者プルダウンで中西さんを選択
   - 保存
   - → 山中さんの行からセルが消える
   - → 中西さんの行にセルが現れる
   - → DB の routeSheetRowId が更新されている (psql 確認)

4. **(未割当)への変更**
   - 担当者プルダウンで「(未割当)」を選択
   - 保存
   - → セルが未割当扱いに (現状の未割当処理に従う)

5. **休憩セルの配置**
   - 「休憩」チェックボックスをONに
   - 利用者・サービス種別プルダウンが disabled or 非表示になる
   - 担当者プルダウンは引き続き選択可能
   - 保存できる

6. **その日のシフト未登録の場合**
   - シフトを1件も登録していない日のセルを開く
   - 担当者プルダウンに「(未割当)」しか表示されない
   - その状態でも保存可能 (担当者は任意)

## 実装上の注意

### A. 既存ロジックの保護
- ガント画面の表示ロジック (residentName / serviceLabel のフォールバック表示) は維持
- ドラッグ&ドロップ機能は壊さない
- 競合検出 (赤枠) は維持
- テンプレ表示モード / 当日インスタンスモードの両方で動作すること

### B. DBスキーマ変更は不要
- residentName / serviceLabel / staffName のカラムはそのまま残す
- 新規データには使わなくなるが、過去データの参照用に保持

### C. OpenAPI 更新の必要性
- CellUpsertSchema (Zod) で residentId/serviceTypeId を required にする変更が必要
- ただし「休憩 (isBreak=true) の場合は不要」というロジックを Zod のリファインで実装:
```typescript
const cellSchema = z.object({
  // ...
  isBreak: z.boolean().default(false),
  residentId: z.string().uuid().nullable().optional(),
  serviceTypeId: z.string().uuid().nullable().optional(),
  // ...
}).refine((data) => {
  if (data.isBreak) return true;
  return !!data.residentId && !!data.serviceTypeId;
}, {
  message: '休憩でない訪問では、利用者とサービス種別の選択が必要です',
});
```

サーバ側 (Express) と クライアント側 (フォームバリデーション) 両方で同じロジックを適用。

### D. テンプレート編集モードでの挙動
テンプレート編集モード (`?mode=template&weekday=X`) では:
- 担当者プルダウンは表示しない (テンプレートは shift_type で行を持つため)
- 利用者・サービス種別はマスタ選択のまま (既存通り)
